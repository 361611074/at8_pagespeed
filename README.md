# at8_pagespeed · 页面加速（Z-BlogPHP）

链接悬停预加载、图片懒加载、DNS 预取——三合一页面访问加速插件。

**输出层优化**：只通过 Z-BlogPHP 官方输出过滤器 `Filter_Plugin_Zbp_MakeTemplatetags`（1.7.x 前台注入点，引用传递 `$tags`，追加 `$tags['header']` / `$tags['footer']`）追加前台资源，另外只注册一个后台菜单项。不注册上传 / 删除 / 发布 / 评论等业务流程相关的 Hook，不建表、不写文件，配置存于系统自带的配置表。

## 功能

### 1. 链接预加载（instant.page v5.2.0 内置）

- 鼠标悬停 / 触摸按下时提前预取目标页，减少点击后的等待；
- 触发延迟可调（默认 65ms，与 instant.page 官方默认一致；数值越大越省流量，0 最激进）；
- **敏感链接黑名单**：链接地址命中关键字即跳过预加载（默认已排除退出登录、后台、购物车、支付、删除、编辑、feed 等），支持后台自定义；
  匹配不区分大小写，并对 URL 编码写法（如 `log%6Fut`）与浏览器归一化后的路径一并比对，降低被改写绕过的可能；
  动态插入的链接（评论翻页、无限滚动等）由 `MutationObserver` 兜底补标。

> instant.page 本身的默认策略也已相当保守：跨域链接不预取、带查询串的链接不预取、非 http(s) 协议不预取。本插件不修改这些默认值。

### 2. 图片 / iframe 懒加载

- 为**视口外**的 `img` / `iframe` 补 `loading="lazy"`（图片另加 `decoding="async"`），后续调度交给浏览器原生懒加载；
- 可设置跳过首屏前 N 张图，避免拖慢首屏大图（LCP）；
- 支持 `data-no-lazy` 属性排除单个元素或整个容器；
- 已有 `loading` 或 `fetchpriority` 属性的元素一律不修改——作者已明确表态时以作者意图为准。

### 3. DNS 预取

- 站点自身域名自动包含；
- 后台可添加第三方资源域名（图床 / 统计 / 字体），不符合域名格式的输入自动丢弃。

## 兼容性

### 运行环境

| 项目 | 要求 / 说明 |
|---|---|
| Z-BlogPHP | 1.7.x（`plugin.xml` 声明 `<adapted>172900</adapted>`，可拦住 1.6 及更早版本） |
| PHP | **5.6 及以上**（`<phpver>5.6</phpver>`）。代码语法与函数最低要求 5.4（用到 `JSON_UNESCAPED_UNICODE`），5.4 / 5.5 未做实测故不作承诺 |
| 实测环境 | PHP 7.3 / 8.2 + Z-BlogPHP 1.7.5 |
| 数据库 | MySQL / SQLite / PostgreSQL 均可——只用系统配置接口读写，不含任何数据库专有语法 |
| 服务器 | 无特殊扩展要求（不依赖 curl / gd / redis 等） |

### 主题与插件

- **依赖系统标准模板变量**：注入点为 `$header` / `$footer`（主题 `header.php` / `footer.php` 中的标准标签）。只要主题按官方规范输出这两个变量即可生效；若主题未输出，本插件会静默不注入，不会报错。
- **`$footer` 需位于 `<body>` 内**：instant.page v5 的触发延迟读取自 `document.body` 的属性，插件在 `$footer` 中写入该属性。若主题把 `$footer` 放到 `<head>`（不符合官方规范），延迟设置不生效，其余功能不受影响。
- 与其它插件无已知冲突：不占用系统 Hook 业务点，仅注册两个过滤器（输出追加 + 后台菜单）。

### 浏览器

- 懒加载依赖浏览器原生 `loading="lazy"`：Chromium 77+ / Firefox 75+ / Safari 15.4+；不支持该属性的浏览器会忽略它，图片仍按原有方式加载，**功能降级但不会报错**。
- 预加载依赖 `prefetch` 与 `MutationObserver`：现代浏览器均可；`MutationObserver` 不可用时仅失去「动态插入链接」的兜底，首屏链接的黑名单标记不受影响。
- 内置的 instant.page v5.2.0 含 ES6 语法，在 IE 等旧引擎中不会执行（错误被隔离在脚本内，不影响页面其它功能）。

### 已知限制

- **懒加载在解析完成后生效**：`loading="lazy"` 由脚本补写，浏览器可能已经为部分图片发起请求，此时属性不会取消已在途的请求。因此实际省流效果**弱于**在 HTML 源码中就带该属性的方案。
- **不处理动态插入的图片**：本插件只在页面加载时扫描一次，由前端脚本在加载后新插入的图片不会被补属性（有意不做全文档监听，避免在动态页面上写入不可预期的属性）。
- **DNS 预取只做域名解析**：不建立连接、不预取资源。
- 加速效果与站点结构、主题图片数量、网络环境相关，**不会有固定数值的提速承诺**。

## 安装

1. 应用中心搜索「页面加速」或上传 zba 包安装（装完记得在插件列表启用）；
2. 后台左侧菜单「页面加速」进入设置；
3. 各功能独立开关，默认开启预加载与懒加载。

安装 / 停用 / 卸载 / 升级的完整测试项与判定标准见 [`RELEASE_CHECKLIST.md`](RELEASE_CHECKLIST.md)。

## 生命周期与数据

| 阶段 | 行为 |
|---|---|
| 安装 | 幂等写入默认配置（仅补齐缺失键，不覆盖用户已保存的值） |
| 启用 | 仅注册两个官方过滤器（前台输出追加 + 后台菜单），无其他副作用 |
| 停用 | 不修改任何数据，前台注入随之停止；再次启用后原有配置继续沿用 |
| 升级 | `UpdatePlugin_at8_pagespeed()` 按 `ConfigVer` 逐级迁移配置，不重建用户数据 |
| 卸载 | **不删除配置**。本插件不建表、不写文件，全部自定义设置只存在系统配置表的一行记录中 |

> **关于「卸载不删配置」**：Z-BlogPHP 1.7.5 的 `DisablePlugin()` 内部会调用 `UninstallPlugin_<id>()`，
> 也就是**停用与卸载共用同一个钩子**；而真正的「删除应用」由应用中心删除插件目录完成，反而不触发该钩子。
> 若在钩子里删配置，用户每次**停用**都会丢失全部自定义设置。
> 因此本插件把配置视为站点级偏好予以保留；如需彻底清除，手动删除配置表中 `conf_Name = at8_pagespeed` 的记录即可。

## 安全与合规

- 不建表、不修改系统文件、不注册业务流程相关的 Hook；
- 配置写操作使用 `CheckIsRefererValid()` 校验（官方写操作标准姿势，校验失败直接终止），后台页要求 `admin` 权限，并额外校验插件已启用；
- 前台输出经 `htmlspecialchars` 转义；DNS 域名按域名格式校验，不符合的直接丢弃；
- 后台页、登录页、`/zb_system/` 下的请求自动跳过注入（判定依据为官方原生标记 `$zbp->ismanage` 与请求路径）；
- 无加密、无混淆、不引用任何外站资源（instant.page 与两个配套脚本均为本地文件）；
- 不读取 `HTTP_REFERER` 做跳转（避免被伪造造成站外跳转，也避免直接访问时的未定义索引告警），保存后固定回设置页；
- 不写任何敏感信息到页面或日志。

## 更新日志

### 1.0.4（2026-09-23）

- **修复「触发延迟」设置完全无效**：instant.page v5 改为从 `document.body` 的 `data-instant-intensity` 读取延迟（v4 才是读 `<script>` 标签属性），原实现写在 `<script>` 标签上无人读取，实际始终走内置默认 65ms。现改为在其执行前写入 `document.body`，并由守卫脚本兜底；
- **预加载黑名单匹配加强**：原来只做原文区分大小写的 `indexOf` 比对，可被大小写（`/Logout`）或 URL 编码（`log%6Fut`）绕过；现改为「原样 + URL 解码后 + 浏览器归一化路径」三重比对，`MutationObserver` 兜底也改为只扫描新增节点、不再全文档重扫；
- **新增容器级预加载排除**：instant.page 只读取 `<a>` 自身的 `data-no-instant`，不支持在容器上一次声明整块排除。现由守卫脚本沿父链查找 `data-no-instant`，命中即为容器内所有链接补标记，导航 / 挂件 / 评论区可整块关闭预加载（动态插入的容器同样生效）；
- **懒加载保守化与性能修正**：新增「已有 `fetchpriority` 属性不处理」与「未渲染 / `display:none` 元素不处理」（后者原先注释已声称跳过但代码并未实现）；祖先 `data-no-lazy` 判定不再依赖 `Element.closest`；改为「先测量、后写入」两趟处理，消除边读边写导致的强制重排；
- **文档**：README 重写「兼容性」为正式说明（运行环境 / 主题与插件 / 浏览器 / 已知限制），去除「零侵入」「任何主题」「几乎零等待」等绝对化表述；**修正 README 中与代码矛盾的「卸载会删除配置」描述**（实际为不删除，见「生命周期与数据」）；
- **元数据**：`plugin.xml` 的 `<phpver>` 依据注释与源码注释对齐（语法最低 5.4、声明下限 5.6 的理由），补充 `<adapted>` 的取值依据。
